# Security requirements: implementation and evidence

Where each required property is implemented, and which tests show it. Paths are relative to `D6-Key-Management/`, which holds the code of D2, D3, D5 and D6. Run the tests with `python -m pytest -v` from that folder (see the root [`README.md`](../README.md)).

| Requirement | Implementation | Tests |
|---|---|---|
| **Correct AEAD usage** | AES-256-GCM only (`AESGCM` from `cryptography`); a new 256-bit key per file; the tag is never truncated; the algorithm is authenticated and any other value is rejected. `vault/symmetric.py`, `vault/hybrid/encryption.py` | `tests/test_symmetric.py`: `TestRoundTrip`, `TestWrongKey`, `TestCiphertextTampering` (every ciphertext and tag byte). `tests/hybrid/test_hybrid.py`: `TestCorruptedCiphertextAndTag` |
| **Proper nonce handling** | A 96-bit random nonce from `os.urandom` for every encryption and for every key wrap; the `random` module is not used | `TestUniqueness` in `tests/test_symmetric.py` (`test_nonces_and_wrapped_deks_never_repeat`, `test_all_randomness_comes_from_os_urandom`, `test_module_does_not_use_insecure_rng`); `tests/hybrid/test_hybrid.py::test_csprng_used_exclusively_for_dek_and_nonce`; `tests/hybrid/test_ecies.py::TestEphemeralKeys` |
| **AAD protection** | Header, algorithm identifiers, timestamp, `filename`, `metadata` and the full recipient list (with each ephemeral key) are the AAD; the same bytes are inside the signature | `tests/hybrid/test_metadata.py` (`TestAadBinding`, `TestTamperingBreaksEveryRecipient`); `tests/hybrid/test_hybrid.py` (`TestTamperedRecipientList`, `TestRecipientRemovalAttack`); `tests/hybrid/test_ecies.py::TestEphemeralKeyTampering` |
| **Signature verification before decryption** | `verify_and_decrypt` and `verify_with_trusted_signers` check the strict parse, the trusted signer, the signature and the replay record before any key is unwrapped. The command line also refuses an unsigned container unless the user says so. `vault/signatures/signing.py`, `vault/keystore/trust.py`, `vault/cli.py` | `tests/signatures/test_signatures.py` (modified ciphertext, metadata, ephemeral key; wrong key; signature removed); `tests/keystore/test_trust.py` (untrusted, forged and revoked signers); `tests/keystore/test_trust_replay.py` (a tampered container is not recorded); `tests/cli/test_cli_hardening.py::test_stripped_signature_is_refused` |
| **Secure key storage** | Argon2id (64 MiB, 3 iterations, 4 lanes, 16-byte salt) and AES-256-GCM with an authenticated format; the password is never stored; unlocked keys are not cached; an existing keystore is never overwritten. `vault/keystore/keystore.py` | `tests/keystore/test_keystore.py` (wrong password, modified keystore, swapped key, backup and restore, stolen keystore alone, never overwritten, RSA refused); `tests/keystore/test_keyring.py`, `tests/keystore/test_revocation.py` |
| **Fail-closed behavior** | Every failed check stops the operation and writes nothing; outputs are created exclusively and never through a link; the library removes a partial output file if writing fails; all failures to open a container share one generic error | `tests/test_symmetric.py`: `TestDiskSafety`, `TestErrorHygiene`; `tests/hybrid/test_hybrid.py::test_disk_failure_mid_write_cleans_up_partial_file`; `tests/cli/test_cli_hardening.py::test_files_are_created_private_and_never_follow_links` |
| **Input validation** | Strict container parser (exact fields and types, no duplicate keys, canonical base64, size limits); `filename` never used as a path; one key-file encoding (single PEM block, `.pem`, at most 16 KiB, expected key type); contact names and fingerprints validated | `tests/test_symmetric.py::TestInputValidation`; `tests/hybrid/test_metadata.py` (`TestInvalidMetadataRejectedOnEncrypt`, hostile filename); `tests/hybrid/test_key_files.py`; `tests/hybrid/test_ecies.py` (low-order and wrong-length keys); `tests/cli/test_cli_hardening.py::test_oversized_and_non_regular_inputs_are_refused` |

## Continuous integration

`.github/workflows/tests.yml` runs the test suite of D2, D3, D5 and D6 on Python 3.11 and 3.12 for every push to `main` and every pull request (eight jobs). Nothing is merged to `main` without a pull request, a review from someone other than the author and a green run.
